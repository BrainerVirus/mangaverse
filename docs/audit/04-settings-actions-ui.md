# Settings, actions and UI consistency audit

Audit of `bugfix/app-flow-audit`, base `0c96b79e`. This is an investigation, not an implementation. Other auditors were working in the same worktree, which was dirty by the end of the investigation; observations are not a clean-commit release certification. **Live** means observed in Chromium against the Vite web dev server, with recorded MangaDex responses where specified. **Static** means code inspection, not a reproduced runtime failure. This report does not assert that all settings were individually tested on reload or that Windows was tested.

## 1. Observed bugs and concrete gaps

### A. Detail Back reopens the reader (live)

1. With a library title and chapter available, open Library → title → Start reading. Open reader chrome and choose Close reader. The title opens.
2. Choose its Back button. **Expected:** return to the library/list or other meaningful origin. **Actual:** the reader opens again.

The reader navigates forward to `/manga/$id` (`apps/web/app/routes/reader.$chapterId.tsx:301-306`); detail uses history back whenever available (`apps/web/app/routes/manga.$id.tsx:328-333`, `apps/web/app/queries/manga-detail-route-helpers.ts:285-295`). This creates a loop. Reader chrome screenshot: `/tmp/audit04-shots/15-reader-chrome.png`; it does not by itself prove the subsequent URL transition. The probe logged both URLs. Coordinate the origin/history policy with the navigation audit.

### B. Title Migrate loses title context (live)

1. Open the recorded MangaDex title, both outside and inside the library; select **Migrate**.
2. **Expected:** a single-title migration handoff or an explicit explanation when this title cannot be migrated. **Actual:** `/advanced/migration?source=mangadex`, with source selected but no title IDs. The same destination is shown in both cases. With no target provider the page shows provider controls but no title selection yet.

`apps/web/app/routes/manga.$id.tsx:377` passes only `activeMapping`; `apps/web/app/queries/manga-detail-route-helpers.ts:297-302` serializes only `source`. An empty ID handoff means all candidates, not this title (`apps/web/app/lib/migration-handoff.ts:81-100`). In contrast library bulk passes `ids` (`apps/web/app/routes/library.tsx:91-101`). A title without a mapping still gets an enabled Migrate button but its handler returns without action (`MangaDetailPage.tsx:525-531`; helper:301); that case is **static**, not live reproduced. Screenshots: `/tmp/audit04-shots/11-migrate-from-detail-not-in-library.png`, `/tmp/audit04-shots/13-migrate-from-detail-in-library.png`.

### C. Cache-limit entry can revert during ordinary editing (live)

On App settings, fill Local cache limit with `20`; after the coalescing interval, it returns to 500 and displays the generic **Could not save settings** toast. Expected: a draft with a clear 50–10240 MiB validation message until corrected; actual: an invalid intermediate value is optimistically applied and written on a 300 ms timer (`apps/web/app/features/settings/components/AppSettingsPage.tsx:227-241`, `apps/web/app/lib/use-coalesced-settings-write.ts:3,36-43`), then rejected by `packages/shared/src/app-settings.ts:36-39` and refetched (`apps/web/app/routes/settings.app.tsx:44-47`). `Number('')` is 0, so clearing the input has the same risk. This is a reported save failure, not a silent persistence loss. A transient screenshot was viewed during the live session but was not saved to disk; no screenshot file is claimed.

### D. Title overrides are not distinguishable from inherited values (live + static)

From detail, choose Reader settings. The URL contains `?title=<manga-id>` and the header says the preferences are for this title, but individual rows do not indicate which values are inherited; there is only **Reset title settings** for all overrides. `settings.reader.tsx:44-47,103-105` has override data, but `ReaderSettingsPage.tsx:716-723,748-756` receives only effective values. `docs/SPEC.md:107-112` and `docs/Design.md:278-284` require the distinction. Screenshot `/tmp/audit04-shots/14-title-reader-settings.png`. The probe changed Page number for the title, waited for durable flush and reloaded: title remained false and global remained true; this demonstrates scope separation for that one field, not every setting.

### E. Settings context return is missing (live)

App settings, reader settings, backup, storage, extensions, theme and Advanced had no in-page Back button in the probe; title-scoped Reader settings has no in-page link back to its originating title. The sidebar and browser history remain available, so these are context/wayfinding gaps, not inaccessible routes. The settings index uses navigation buttons (`apps/web/app/features/settings/components/SettingsIndexPage.tsx:40-47`); nested settings render an outlet without a parent return (`apps/web/app/routes/settings.tsx:10-21`). Screenshots: `/tmp/audit04-shots/18-settings-index.png`, `/tmp/audit04-shots/nav-_settings_app.png`, `/tmp/audit04-shots/nav-_settings_reader.png`, `/tmp/audit04-shots/nav-_backup.png`, `/tmp/audit04-shots/nav-_storage.png`, `/tmp/audit04-shots/nav-_theme.png`.

Quick reader sheet defaults its scope to **This title** on each open (`packages/reader/src/components/reader-settings-sheet.tsx:239-256`). It coalesces snapshots and writes global plus title layers (`apps/web/app/routes/reader.$chapterId.tsx:133-185,188-203`; `features/settings/save-title-reader-settings.ts:27-44`). A title-only edit can write a stale captured global snapshot if another session changed global settings in the meantime; this is a **race hypothesis**, not reproduced. The two-layer write is sequential, not visibly transactional, so failure between writes can leave partial scope changes. In the full title settings page, reset has a separate mutation and does not cancel/serialize a queued writer (`settings.reader.tsx:54-95,97-109,121-124`): a pending edit can potentially recreate overrides after reset. Contrast quick-sheet reset, which cancels its timer (`reader.$chapterId.tsx:277-280`). Test both races deterministically before asserting occurrence.

**Onboarding, theme, provider and durability:** Onboarding state is validated and stored under its own app-setting key (`features/onboarding/save-onboarding-state.ts:9-20`). Its theme, app, and reader mutations update the same rows; finish/skip and provider-install transition call `flushLocalDb` before navigating (`routes/onboarding.lazy.tsx:89-105,109-155,175-198,218-248`). `flushLocalDb` catches errors instead of rejecting (`lib/local-db.ts:481-492`), so the finish `.then` can navigate even after a failed checkpoint; the banner may report failure, but the comment's durable-before-navigation promise is not guaranteed. Test forced IndexedDB failure. Theme has its own global row (`packages/db/src/repositories/settings.ts:119-147`) and provider settings have per-provider rows (`:203-245`); their entire editors and reload behavior were not individually audited here.

**Sessions and Windows:** Web uses in-memory sql.js plus a scheduled IndexedDB snapshot (`lib/local-db.ts:456-473,546-554`), external storage/visibility events replace the handle and invalidate queries (`providers/local-db-provider.tsx:140-165`). The settings writer's 300 ms timer outlives a component unmount but not a document/process termination; immediate reload or quit before timer/flush is an unverified loss window. Electron's host opens `app.getPath('userData')/mangaverse.sqlite`, with page files in `userData/pages` (`apps/desktop/src/main/index.ts:121-125,196-215`), not a Windows-specific hard-coded path. Desktop change broadcast omits settings and reader-preference tables (`packages/db/src/data-host-protocol.ts:30-42`), so another owned window's cached settings need not update promptly; settings have a ten-minute stale time (`apps/web/app/queries/query-timing.ts:5-11`). Full-row concurrent writes also risk last-writer-wins lost updates. Both are static concurrency findings, not live Windows reproductions. Packaged Windows permissions, restart, profile migration, app quit, and native SQLite/IPC failure behavior remain untested.

## 5. Intended state machines and finite TLA+ proposal

**Settings:** `loaded(durable, version)` → `draft` on edit → `pending(seq, value, scope)` on schedule → `saving` on flush → `saved` only on durable acknowledgement → refetch/reconcile. Failure → visible error + durable value or retained retryable draft. Reset must invalidate/cancel earlier pending changes for that same scope; newer accepted edits must not be overwritten by older completions. Unmount, reload, multiple windows and host restart are explicit transitions, not implicit success. Distinguish global, title override and inherited effective value.

**Manga action:** `idle(context)` → `confirm/preview` when destructive or migrating → `pending(action,target,revision)` → committed + observable state/feedback or failed + preserved context/retry. On navigation, carry explicit manga/mapping/chapter IDs and return origin; no success for a null target. A migration preview/commit must bind the actual selected title(s), source and target.

Proposed finite TLA+ model (not implemented or model-checked): variables `durable[scope]`, `cache[window,scope]`, `draft[window,scope]`, `queued[window]`, `inFlight`, `seq`, `ack`, `scope`, `contextTitle`, `contextMapping`, `actionTarget`, `route`, `history`, `failure`. Actions `Edit`, `Flush`, `Commit`, `Fail`, `Reset`, `Reload`, `CloseWindow`, `ExternalCommit`, `Refresh`, `OpenTitle`, `OpenReader`, `CloseReader`, `Back`, `StartMigration`, `ConfirmAction`, `CompleteAction`. Bound to two windows, global + two title scopes, two values/fields, two titles/mappings and at most two pending operations; include nondeterministic delayed/reordered replies and storage failure. Check:

* `SavedSurvivesReload`: after a **durable acknowledged** write, reload returns it unless a later successful write/reset to that scope superseded it. Do not require unacknowledged drafts to survive.
* `LatestAcceptedWins`: stale acknowledgements/refetches never erase a newer pending edit; reset fences older queued/in-flight title writes.
* `ActionHasEffect`: an enabled, accepted action eventually changes the intended target, navigates to its intended destination, or exposes an explicit failure; bounded fairness required for liveness.
* `ActionTargetMatchesContext`: a single-title migration carries that title and source; chapter actions target the currently displayed chapter/mapping; Back does not create an unintended reader/detail cycle.
* `ScopeIsolation`: title edits do not alter global/other titles; global updates do not erase explicit unrelated overrides. Add atomicity for two-layer changes and cross-window conflict scenarios.

## 6. Ranked root-cause hypotheses and red/green tests

1. **Navigation has no stable origin contract** (live A, E): pass a validated return target or replace reader history deliberately. RED: library → title → reader → close → Back reaches library, not reader; also discover/search entry, direct deep link, title settings return, browser history, and missing origin. GREEN after agreed navigation policy.
2. **Migration handoff is provider-centric rather than title-centric** (live B): bind single-title IDs and source, restrict or explain non-library/unmapped titles. RED: two titles under same provider; migrate one and assert only that ID is offered through preview/apply, plus no-mapping disabled/explained. Verify bulk handoff remains intact.
3. **Settings persistence mixes drafts, optimistic cache, coalesced timers and full-row saves** (live C; concurrency and early-quit are hypotheses). RED: clear/type valid `200` slowly without a premature error; invalid final value shows field-specific error; reverse write completions, reset during queued title change, close/reload before/after durable acknowledgement, fail IndexedDB/native IPC, two windows editing different fields, and retry. GREEN requires serialized/versioned or transactional writes, explicit acknowledgement, conflict policy and deterministic durable checkpoint, not just a longer timeout.
4. **Stored settings without product consumers / invisible scope** (static global locale/languages, live D): either wire capability-aware consumers or explicitly disable/remove unsupported controls. RED: change global language/locale and assert actual ranking/localization or explicit unsupported state; title rows show inherited versus override; changing global respects overrides; reset restores inheritance.
5. **Independent control implementations lack common semantics** (static): unify settings row, back and selection affordances. RED: zero selection disables bulk status, keyboard/accessible descriptions work, back control stays stable in loading/error/loaded, narrow/coarse-pointer and focus snapshots. Include failure feedback and avoid toast + inline duplicate errors.
6. **Actions lack explicit target/atomic outcome contracts** (static risks): test mapping switch failure between writes, source with no chapters and old last-read elsewhere, duplicate merge/split errors, rapid double bulk click, download engine unavailable, cover URL errors and migration rollback; assert IDs, durable DB state, pending/disabled state and feedback.
